# Tests

Automated regression tests for Grandmothers voice by Kayock. They run the **real
shipped code**: the DOM-free core functions are extracted verbatim from
`Grandmothers_Voice_by_Kayock.html` (between the `CORE-BEGIN` and `EXPORTS-END`
markers) and executed in a Node sandbox, so the suite always tests exactly
what ships — not a copy.

## Running

Requires Node.js 18 or newer. No packages to install.

```
node run_tests.mjs            # full suite — expect "ALL TESTS PASSED" and exit code 0
node run_tests.mjs --perf     # adds the 10,000-person performance benchmark
```

From the project root you can also run `node tests/run_tests.mjs`.

## Regenerating fixtures

The GEDCOM fixtures are generated by a script (fully synthetic — every
person, place and date is invented):

```
node fixtures/make_fixtures.js
```

Fixtures produced:

| File | Purpose |
| --- | --- |
| `basic_v551.ged` | UTF-8 5.5.1 tree with shared notes, citations (QUAY), multi-part names, occupation/residence events, media records |
| `ansel_v551.ged` | ANSEL-encoded file with combining diacritics (Peña, Cristóbal) |
| `cp1252_v551.ged` | Windows-1252 "ANSI" file (é, ü, ö) |
| `v70.ged` | GEDCOM 7.0 tree with ISO dates, `TRAN` media, 7-style citations |
| `edge_cases.ged` | duplicate xref, unresolved refs, child-is-spouse, same-person-both-roles, birth after death, CONT/CONC, inline BLOB, malformed line |
| `minimal.ged` / `empty.ged` / `garbage.ged` | degenerate inputs must not crash |
| `large_10k.ged` | 10,000 people / 3,340 families for performance runs |

## What is covered (83 tests)

1. Basic 5.5.1 parsing: people/families counts, names with surname
   extraction, event-level notes and citations, shared-note resolution,
   source record fields, media records, inline media.
2. Encodings: ANSEL → Peña/Cristóbal, Windows-1252 → é/ü/ö, UTF-8 label.
3. GEDCOM 7: spec detection, media record, citation page, ISO dates.
4. Edge cases & diagnostics: duplicate xref, unresolved FAMC/FAMS/CHIL,
   SAME_SPOUSE_BOTH, CHILD_IS_SPOUSE, BIRTH_AFTER_DEATH, event-level
   note/citation preservation, CONT/CONC leading spaces, malformed lines,
   inline BLOB, empty/garbage inputs.
5. Date parsing: ABT/EST/BEF/AFT, BET…AND ranges, FROM…TO, dual years,
   phrase dates, certainty flags.
6. Tree identity stability; living classification; redact / redact-names /
   exclude privacy modes incl. family event stripping.
7. Duplicate suggestions: evidence and confidence, relatives never flagged.
8. Refinement backups: v1 conversion, merge add/skip/conflict, "both"
   resolution with attribution, malformed backup rejection.
9. Reports: diagnostics MD/JSON, source quality, suggested changes.
10. ZIP writer: Unicode + binary entries verified by an **independent**
    reader (Python `zipfile`, CRC check), name sanitising and dedupe.
11. Vault exports: Obsidian/Logseq structure, wiki links, media embeds
    with relative paths, single-file Markdown.
12. Booklet: cover, chronology, sources, memories with attribution,
    surname scope, privacy notice.
13. Explorer: data JSON safety (script-tag escaping), view tabs, syntax
    guard (the generated inline script must parse), linked-media paths.

The **[v2.1] regression section** adds 22 tests for the privacy repairs and
rebranding: leakage markers (private names, media paths/titles/bytes) across
explorer HTML, booklets, diagnostics Markdown and vault ZIP contents;
non-mutating export builds (master data snapshotted byte-for-byte across
four privacy modes and toggle combinations); sequential mode transitions;
frozen tree-identity and storage-key compatibility; v1 backup merging;
branding (new name present, zero old-name occurrences); Southwest palette
hexes, theme labels and reduced-motion rules; launchers and legacy stub;
fresh-source build reproducibility (rebuilt HTML byte-identical to shipped).

## Adding tests

Follow the existing `test('name', () => { … })` pattern. Anything you add
must keep passing on Node 18+ without network access. If you change the
explorer template, the syntax guard test will catch quoting mistakes.
